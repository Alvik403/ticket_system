Электронная очередь

Цифровая система управления потоком посетителей на одной площадке. Клиент получает талон по QR без регистрации, сотрудник автоматически получает следующий совместимый талон, администратор управляет каталогом услуг и аналитикой.

1 площадка фокус MVP — одна точка обслуживания
0 регистраций клиент заходит анонимно по QR-ссылке
PostgreSQL единственный источник истины очереди
OIDC + BFF сотрудники и админы через Keycloak

Зачем

Проблема и решение

Бумажные талоны и ручное распределение создают очереди, ошибки назначения и отсутствие прозрачности. Электронная очередь автоматизирует выдачу, назначение и учёт обслуживания.

⚠️

Боль

Посетители не знают своё место в очереди. Сотрудники вручную выбирают следующего клиента. Нет единой статистики по времени ожидания и загрузке окон. При сбое теряется порядок обслуживания.

✅

Решение

QR ведёт на публичный интерфейс. API выдаёт талон с секретом, диспетчер назначает совместимый талон свободному сотруднику. Все переходы фиксируются событиями. Администратор видит операционные метрики и управляет каталогом.

Участники

Роли и интерфейсы

Три типа пользователей работают через разные точки входа. Решения о доступе принимает только серверный API.

Клиент (посетитель)

Анонимный пользователь. Сканирует QR на площадке, выбирает услугу, получает номер талона и отслеживает статус на телефоне.

  • client-web
  • /api/public/*
  • без учётной записи
  • секрет талона в cookie

Сотрудник (оператор)

Авторизуется через OIDC. Переключает статус «доступен / пауза». Получает назначенный талон, вызывает клиента, начинает и завершает обслуживание.

  • staff-web
  • /api/employee/*
  • роль EMPLOYEE
  • автоназначение

Администратор

Тот же интерфейс сотрудника плюс права на каталог услуг, отчёты, экспорт метрик, управление совместимостью и аудит действий персонала.

  • staff-web
  • /api/admin/*
  • роль ADMIN
  • аудит экспорта
Пользовательские сценарии

Основной поток обслуживания

От сканирования QR до завершения визита — восемь шагов с серверной валидацией на каждом переходе.

1

QR на площадке

Статический QR содержит только публичный код площадки (?site=MAIN). Без секретов и персональных данных.

2

Выдача талона

Клиент выбирает услугу. API генерирует 256-битный секрет, сохраняет SHA-256, возвращает человекочитаемый номер (например, A-042).

3

Ожидание в очереди

Талон в статусе WAITING. Клиент видит позицию и текущий статус на экране телефона.

4

Автоназначение

Свободный сотрудник (AVAILABLE) получает первый совместимый талон: приоритет по убыванию, затем время создания. Блокировка FOR UPDATE SKIP LOCKED.

5

Вызов клиента

Сотрудник нажимает «Вызвать». Талон переходит в CALLED, клиент видит номер окна.

6

Начало обслуживания

Клиент подошёл — статус IN_SERVICE. Сотрудник переходит в BUSY.

7

Завершение

Обслуживание завершено — COMPLETED. Сотрудник снова AVAILABLE, диспетчер назначает следующий талон.

8

Исключения

Отмена (CANCELLED), неявка (NO_SHOW), переназначение (возврат в WAITING) — каждое действие пишет неизменяемое событие.

Модель данных

Машины состояний

Талон

WAITING → ASSIGNED → CALLED → IN_SERVICE → COMPLETED

Из WAITING, ASSIGNED или CALLED — отмена. Из CALLED — NO_SHOW. Переназначение возвращает талон в WAITING.

Сотрудник

OFFLINE AVAILABLE RESERVED BUSY PAUSED

RESERVED и BUSY устанавливает сервер. OFFLINE, AVAILABLE и PAUSED выбирает сотрудник при отсутствии активного назначения.

Отказоустойчивость

Redis можно восстановить — сотрудники войдут повторно, очередь не теряется. PostgreSQL — единственный источник истины с PITR. При потере связи UI перечитывает состояние с API.

Compliance

Безопасность и персональные данные

🔒

Аутентификация

OIDC Authorization Code + PKCE на сервере. Токены не попадают в localStorage. Сессии в Redis, cookie — только session id.

🎫

Секрет талона

256-битный случайный секрет. В БД — только SHA-256. QR не содержит секретов. Логи не пишут секрет, cookie и IP целиком.

🇷🇺

Production

Размещение в РФ, TLS, MFA, WAF, rate limiting, миграции вместо synchronize, шифрованные backup, централизованный аудит.

Аналитика

Ключевые метрики

Объект Метрика Формула / правило
Талон Время ожидания IN_SERVICE − CREATED
Талон Время обработки COMPLETED − IN_SERVICE
Талон Полный цикл COMPLETED − CREATED
Сотрудник SLA Доля обслуживаний ≤ ServiceType.slaSeconds
Сотрудник Типичное время Медиана (p50) длительности обработки
Операции Здоровье очереди Число WAITING, возраст старейшего, зависшие ASSIGNED/CALLED

Персональные показатели сотрудников — только ADMIN, с аудитом при экспорте. Все метки времени — UTC на сервере, отображение — в часовом поясе площадки.
